# weichao.ren 全面体检

检查日期：2026-09-06。代码基线：`28bf771`。本次是审查，未修改站点业务代码、依赖声明或部署配置。

## 结论

项目具备适合个人站的技术骨架：Astro 预渲染内容页、React 交互岛、严格 TypeScript、统一内容集合和永久链接函数。继续沿用这套架构是合理的。

最需要投入的地方是发布可复现性、内容迁移完整性、响应式与可读性，以及项目展示的说服力。审美上，目前是一份整洁、克制的项目目录，但个人辨识度偏弱。真实作品和经历很丰富，页面还没有充分呈现这些价值。

优先级定义：P1 为下一轮应优先修复的问题；P2 为影响体验、维护和传播的改进；P3 为可择机处理的精修。本次没有确认整站不可用或生产环境正在遭受攻击。

## 优先修复

### 1. P1：默认安装不能复现，部署又绕过本地质量检查

`npm ci` 报锁文件缺少 `esbuild@0.28.2` 及平台依赖。本次必须加 `--legacy-peer-deps` 才能使用现有锁文件完成安装。普通 `npm install --no-package-lock` 的补救尝试还触发了 npm 10 的 `edgesOut` 内部错误；不能据此认定所有 npm 版本都失败。

`package.json:11` 的 build 是 `astro check && astro build`，但 `vercel.json:2` 明确使用 `astro build`，因此部署不会执行这里的类型检查。仓库也没有 `.github/workflows`。

建议：确定并声明 Node/npm 版本，按同一安装策略重新生成锁文件；让全新目录的标准 `npm ci` 成功。统一线上构建入口为经过验证的 package script，并设置检查、测试和构建门禁。不能把临时加 legacy 参数视为问题已经解决。

验收：全新 checkout 的安装、22 个现有测试和完整构建通过；故意加入类型错误时，发布检查必须失败。

### 2. P1：聊天接口缺少运行时输入校验

位置：`src/pages/api/chat.ts:31`、`:41`、`:74`，`src/lib/llm.ts:49`。

本地向 `/api/chat/` 分别发送 `null`、`{"messages":[null]}`、`{"messages":[{"role":"user","content":123}]}`，均得到 500。`request.json()` 能成功不代表结构合法；错误处理又继续访问坏对象，所以兜底本身也会抛异常。

建议：用现有 Zod 验证顶层对象、消息角色、字符串内容、数量和长度，非法输入统一返回 400 JSON；设置请求体和输入总量上限。客户端也只发送需要的历史。当前 `.slice(-10)` 仅限制进入模型的条数，不能限制单条长度，也不能阻止服务端先解析过大的请求。

验收：上述坏输入返回稳定的 400；正常静态回答为 200；超限和模型失败各有明确行为及接口测试。

### 3. P1：项目卡片在中等宽度严重挤压

位置：`src/pages/projects.astro:184`、`:189`，`src/components/ProjectCard.astro:146`、`:204`、`:287`。

768px 时外层仍为两列，内部又保留图片、正文、操作三列。实测 AquaSight 和 LLM Quota Watchdog 的标题区域约 40px，英文完整宽度分别约 99px、96px，出现裁切和逐词堆叠；说明文字也变成狭长竖列。390px 和 1440px 正常不能覆盖这个问题。

建议：用卡片实际宽度决定内部布局，或者提前调整外层断点；主操作移到正文下方。验证 720、760、768、820、1024px 附近，而不只验证两种设备。

### 4. P1：文字对比度不足是全站问题

位置：`src/styles/global.css:20`、`:36`，以及使用这些 token 的按钮、日期、分类和状态。

axe 在文章列表检测到 74 个对比度失败节点。蓝底 `#0ea5e9` 上白字约 2.77:1；`#a3a3a3` 在 `#fafafa` 上约 2.41:1；蓝色小标签约 3.56:1。普通小字号文字应达到 4.5:1。这里统计的是重复节点，不是 74 种不同缺陷。

建议：保留蓝色品牌方向，分别定义适合背景、正文链接、状态文字的颜色；提高次要文字对比度。10–12px 的项目操作、状态和页脚文字应适度增大。

### 5. P1：手机文章目录事实上不可见

位置：`src/layouts/PostLayout.astro:118`、`:142`，`src/components/TableOfContents.astro:22`。

目录组件写了移动端 details，但整个组件被放在小于 1024px 就 `display:none` 的侧栏里。因此移动目录没有显示机会。29 篇文章具备至少三个 h2/h3，均受这层布局约束影响。实测 source-Aspects 正文在 390px 下长约 29,211px，手机读者尤其需要章节跳转。

建议：正文前放置移动端目录；桌面维持侧栏。设置标题滚动偏移，避免粘性导航遮住锚点。另将旧文正文标题规范化，避免 h1 排除在目录之外。

### 6. P1：迁移检查假通过，旧订阅入口中断

位置：`scripts/verify-urls.py:24`、`:87`、`:124`，`src/pages/posts.xml.ts`。

验证脚本写死旧 Mac 的绝对路径，在当前环境读到 0 篇文章，仍打印 `Failed: 0` 并以状态 0 退出。它没有实际请求历史 URL，而且复制了一份与 TypeScript 不同的日期处理逻辑，不能证明迁移完整。

Git 历史中的旧订阅文件为 `feed.xml`，线上当前 `/feed.xml` 返回 404，新入口为 `/posts.xml`，旧订阅者可能无法继续收到更新。另确认旧文中的 `/ios/2018/12/27/package/l` 最终返回 404；`2019-08-01-vest-package.md:28` 的 `//ios/...` 会被当作以 ios 为主机的外站地址。

建议：补旧 RSS 重定向，建立历史 URL 固定清单；从构建结果验证站内链接和资源。无文件、重复地址、缺失资源必须失败。将“一次迁移的 61 篇基线”与“未来允许继续新增文章”分开。

### 7. P1：部署文档存在会直接带偏操作的过时说明

详见后面的规则审查。最直接的错误是部署目录 `production`、Node 20、向 `src/content/life/` 写新文章。这些会导致部署失败或新增文章不被加载，应与程序缺陷同批修复。

## 内容、SEO 和传播

### 8. P2：61 篇文章缺少独立摘要

位置：`src/layouts/PostLayout.astro:45`、`src/layouts/BaseLayout.astro:21`、`src/pages/posts.xml.ts:27`，以及 `missing-summaries.md`。

实测 61 篇 HTML description 都退回站点个人介绍；列表没有内容摘要，RSS description 也为空。文章之间的主题差异没有体现在这些入口。搜索引擎可能自行重写摘要，但这不是可控的内容策略。

建议：先补首页四篇和最重要的十篇，随后补齐。每篇 1–2 句说明“解决什么问题、适用于什么条件”。新增文章要求非空摘要；历史文章可设限期清单。

### 9. P2：规范域名与线上重定向冲突

位置：`astro.config.mjs:7`、`src/lib/seo.ts:5`、`src/layouts/BaseLayout.astro:23`、`public/robots.txt`。

线上 `weichao.ren` 返回 308 跳到 `www.weichao.ren`，页面 canonical、OG URL、sitemap 和 RSS 则写无 www 域名。这会增加抓取和分享跳转，发出不一致的规范化信号，不能直接量化为搜索排名损失。

建议：选定实际主域名后统一；`.env.example` 声称支持的 `PUBLIC_SITE_URL` 当前并未被配置消费，应实现或删除这个声明。

### 10. P2：正文语义、长内容和链接还需要一次迁移清理

55 篇文章在页面标题之外还有正文 h1。`PostLayout.astro:213` 只改变了视觉字号，没有改变标题语义；目录又只取 h2/h3。移动正文还叠加两层 24px 内边距，390px 宽度下实际正文仅 294px。

实测 iOS-App-thin 的长行内命令越过右边界。建议正文只保留文章标题这个 h1，修正章节层级；统一长链接/行内代码换行和表格横向滚动；减少手机重复边距。19 张正文图片没有设置 loading，绝大多数也没有成对尺寸信息，应补懒加载与尺寸以减少跳动。

`postSlug()` 直接截去 11 个字符，已使 `2024-04-2-2024-okr.md` 的 slug 变成 `024-okr`。修正时必须同时保留现有链接重定向；UTC 日期与原文当地日期不一致的个案也应按旧地址核对，不能批量“规范化”后丢掉兼容。

### 11. P2：分享图有基础，但默认图与缓存策略可以改善

抽查的中文文章 PNG 正常，这项不是当前全站故障。首页等普通页面仍使用 `og-default.svg`，部分社交抓取器对 SVG 支持有限，建议统一准备 PNG/JPEG。

`src/pages/og/[...slug].png.ts:28` 在运行时从外部字体 CDN 拉字体，没有显式超时或本地图备用路径。可改为随项目携带必要字体，稳定生成分享图。

`vercel.json:9` 和 OG 响应将不带内容哈希的图片缓存为一年 immutable。相同文件名替换截图/二维码时，老客户端可能持续看到旧图。建议使用版本化文件名，或缩短可变 URL 的缓存并允许重新验证。

## 聊天、可靠性与安全边界

### 12. P2：关键词先命中策略误答，且会跳过模型

位置：`src/data/knowledge.ts:33`、`:97`，`src/components/Chatbot.tsx:135`。

匹配条件是 `includes()`，联系条目含单字符 `x`。线上输入 Linux，实际返回邮箱/GitHub/X 联系方式。含 `hi` 的英文词和多意图问题也可能错配；“介绍你的项目”可能先被“介绍”抢走。

建议：短词使用完整词匹配；明确问题使用优先级或简单评分；无足够把握时进入模型/明确兜底。补反例测试。知识库里 `/projects`、邮箱等输出当前是纯文本，应安全渲染为可点击入口；没有必要仅为此添加完整富文本系统。

### 13. P2：错误状态、超时和键盘体验不够完整

浏览器和上游请求都设置 8 秒，浏览器预算包含网络和冷启动，会提前于服务端完整预算结束。客户端将 429、网络失败等统一改成普通静态回答，用户无法区分“不会回答”和“服务暂不可用”。

线上 Escape 可关闭聊天，但当时焦点仍停在已隐藏输入框；axe 还指出聊天滚动区不能获得键盘焦点。移动菜单 Escape 没有关闭逻辑。建议分层设置超时、显示明确错误/重试状态、关闭后还原焦点、让聊天记录可键盘滚动。聊天输入字号 14px，iOS 聚焦缩放和软键盘遮挡仍需真机确认。

### 14. P2：进程内限流不能作为全站模型预算

位置：`src/lib/rate-limit.ts:13`，`src/pages/api/chat.ts:11`。

Map 的 60 次/小时是单进程状态，多实例和冷启动没有共享计数。没有完成线上伪造 IP 或绕过测试，不应声称 Vercel 的代理头可以直接被绕过。

建议：如继续开放付费模型，补明确的全局预算和共享限流或平台规则；低流量纯静态问答场景则无需引入数据库。日志记录响应来源、耗时和错误类别即可，默认不要记录访客完整对话。

### 15. P2：旧公开资源包含可执行历史网页

`public/posts-legacy/xmr.html:3`、`xmr70.html:3` 加载第三方 CoinHive 脚本并调用 `miner.start()`，`xmrsimple.html` 引用另一第三方挖矿界面；构建会原样复制这些 HTML。

这确认的是遗留代码与发布路径，不代表这些历史服务今天仍工作。本次没有执行挖矿页面。建议保留技术历史时改为静态源码/说明，移除直接执行入口；公开旧资源应有用途和保留策略。

`src/data/personal.ts` 还在公共项目页展示局域网和 Tailnet 工具入口。对普通访客不可用且分散页面目的；可迁移到个人书签。仅仅出现地址不等于鉴权被突破，本次没有测试这些私有工具的访问控制。

### 16. P2：旧依赖覆盖项需要复核

`package.json:36` 将 fast-uri 锁到 3.1.5。本次 npm audit 报告该版本的 URI 规范化相关 high 公告，修复范围从 3.1.6 开始；安装后的两项 high 记录是 fast-uri 及受其影响的 ajv。

`npm ls` 显示这条链来自 `@astrojs/check -> language-server -> yaml-language-server -> ajv -> fast-uri`。未证明这些漏洞可从本站生产 API 利用。建议更新/解除不再必要的 override 后验证依赖树与构建，不要把“曾为安全加入的固定版本”永久冻结。

## UI、审美与信息组织

以下是设计判断，不与已经复现的程序缺陷混为一谈。

| 区域 | 当前观感及问题 | 推荐方向 |
| --- | --- | --- |
| 导航 | 英文主导航、中文主体，能用但语言策略不统一；标识较弱 | 面向中文读者统一命名，保留有意义的产品英文名；让 lazy / 韦超成为清晰身份 |
| 首页首屏 | 经历真实，但长句承载整个标题，名字只有小字；与下一节起始线略不一致 | 强化姓名和一句当前定位；把具体经历作为支持信息；统一内容对齐线 |
| 精选作品 | 5 个项目同等强调，截图小到无法辨认，二维码承担了产品封面 | 先精选 2–3 个最能代表当下的作品，用可读的真实截图；二维码作为进入方式，另补产品实景 |
| 项目详情 | 多数分类行隐藏 description，访客只能看名字和语言；精选项目又在分类重复出现 | 每行至少提供一句用途；重要作品写简短案例：问题、成果、你的贡献、限制、入口 |
| 文章列表 | 日期已经出现两次，蓝色日期方块比标题更抢眼；首页最新文章停在 2024 | 用“精选文章”辅助时间存档；缩小装饰日期块，让主题和摘要成为视觉中心 |
| About | 真实而个人化，但自我否定段落较长，旧“现在”语境缺时间 | 保留声音，先介绍当下做什么、可合作什么；长反思归入带日期的个人记录；可加入有故事的本人/户外照片 |
| Now | 读者先看到最旧的六月，“最近”要往下找 | 最新状态置顶，历史保留；展示明确更新时间，不必承诺每月更新却无法长期兑现 |
| 页脚 | 导航、订阅、联系方式完整，但浅灰小字过多，手机占用较长 | 提升对比度并压缩重复信息；RSS 入口值得保留 |
| 整体气质 | 近白背景、蓝色点缀克制，卡片和留白有秩序，但个人辨识度不足 | 保持简洁，以真实作品、经历、照片和更具体的文字形成记忆点 |

建议审美关键词：真实、精确、有个人经历、作品可验证。首轮不需要增加复杂动画、主题系统或重新换框架。图片质量与信息层级的收益明显高于增加装饰。

## 性能与底层维护

首页 Home NAS 图片实际传输约 450,739 bytes，桌面显示仅约 160×100px；AquaSight 约 100KB，二维码约 98KB。最值得先做的是按展示尺寸生成多档 WebP/AVIF 和 srcset。适当保留高清查看入口，避免只剩压缩缩略图。

部分图片直接来自 `raw.githubusercontent.com`。本次均加载成功，但对中国大陆读者的稳定性需要单独实测；可在构建时下载、优化并同域托管。

首页聊天相关三个 JS 响应合计约 67KB 传输量，生产最大 client chunk 为约 181KB 未压缩。对个人站不算失控，但浮动聊天默认关闭，可评估点击后再加载。文章页未启用聊天这一点值得保留。

`public` 共约 40MiB，主要是历史 PDF、zip 等文件；这个数字不等于首页加载 40MiB。整理它们的价值主要是维护和发布清晰度，不应误报为首屏性能灾难。

目前无需为 61 篇静态文章引入数据库、搜索后端、微服务或复杂状态库。应优先增加少量高价值检查：URL 固定样例、坏 API 输入、搜索和聊天的浏览器冒烟、断点截图、站内资源检查。

构建和 dev 同时运行期间曾复现 `_jsxDEV is not a function`，聊天岛消失；构建结束后重启 dev，聊天恢复且浏览器无错误。这里记录为开发流程/缓存交互现象，未视为线上缺陷或持续故障。回归时避免构建与开发共享中间产物相互干扰。

### 哪些规则保留，哪些应该放宽

- 保留永久链接稳定要求。但用明确兼容样例和重定向检查落实，不能仅靠“保持旧 URL”注释。
- 保留 TypeScript strict、服务端保管 Key、内容/项目数据集中维护、未知问题不编造。这些有直接价值。
- 保留 `nowEntries` 升序契约：`now.astro` 用最后一个元素取最新，已有测试保护。以后可让读取端按日期取最大，减少人工排序依赖。
- 将 `global.css:2` 的“tokens locked, never inline”改为“共享视觉值用 token；数据驱动颜色、动画索引可用局部 CSS 变量”。代码本来就存在语言色和 `--i` 内联样式，绝对禁止会误伤合理实现；token 应允许因可访问性问题调整。
- “单一品牌色”可保留为视觉方向，不应禁止错误/成功等语义颜色或真实照片色彩。
- “61 篇文章”只作为历史迁移基线，不能成为未来文章总数上限。
- `missing-summaries.md` 目前仍准确，不是过时文件；问题是清单没有进入日常发布流程。应区分“历史欠账清单”和“新增内容必须符合的规则”。

### 建议新增的规则草案

建议以后在根目录放一份约一页的 AGENTS.md，具体格式化和机械要求交给自动检查。以下仅为草案，本次没有创建生效中的代理规则文件。

```markdown
# 项目约定
```

## 建议推进顺序

1. **发布基础与正确性**：修锁文件和 Node 说明、统一构建入口、更新错误部署文档、修输入校验、恢复 RSS、修假通过验证。
2. **阅读和响应式**：修 768px 卡片、颜色对比度、手机目录、长文本、标题层级和正文边距。
3. **内容和展示**：补重点文章摘要，精选 2–3 个作品，换可读截图，补用途/成果；统一当前个人介绍和 Now。
4. **传播与持续维护**：统一域名、图片格式和缓存、清理可执行旧资源、修关键词匹配和聊天反馈、加入少量自动回归。

建议验收目标：标准安装可复现；主要路径没有断链；非法 API 输入不产生 500；代表页面无已知 AA 对比度失败；中间断点不裁切；新增文章都有摘要；重要项目能让陌生访客在短时间内理解用途并找到入口。
