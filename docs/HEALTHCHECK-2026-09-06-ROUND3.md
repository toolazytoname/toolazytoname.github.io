# 第三轮审核结论

日期：2026-09-06。范围：当前未提交工作区，结合第二轮报告复核。未修改应用源码、依赖声明或部署配置；本轮新增报告和浏览器证据。

结论：还需要一次范围明确的小修复。本轮没有复现第二轮的长文章正文空白，完整 CI 也已通过。当前确认的主要剩余缺陷是聊天异常恢复和 URL 校验遗漏，均列为 P2，不建议因此重新设计网站或更换技术架构。

## 确认需修复

### 1. P2：首次加载聊天失败后，按钮永久禁用

位置：`src/layouts/BaseLayout.astro:131`、`:132`、`:137`。

点击入口先 disabled，再动态 import，监听器还配置 once；失败没有 catch 和恢复路径。在生产构建产物上用浏览器拦截一次 mount-chat JS 请求，确认按钮仍 disabled、聊天面板数量为 0，并出现未处理的动态导入失败。恢复网络后当前页面也没有再次点击的机会。

建议：捕获加载失败，恢复按钮及可重试监听，成功挂载后才移除入口。用“首次失败、网络恢复、再次点击成功”验收。延迟加载本身可以保留。

### 2. P2：重试旧错误会删除后续成功对话

位置：`src/components/Chatbot.tsx:181`、`:292`、`:298`。

重试现在绑定到了正确的问题，解决了第二轮的错发；但 lastRetryableIndex 会一直指向最近的历史错误，即使之后已经有成功回答。retryAt 再 slice 到错误之前，丢弃后面的所有消息。

构建产物的浏览器复现：先发送“苹果甲”并模拟 503，再发送“有哪些项目”获得静态成功回答。点击仍显示的重试后，用户消息从 `[苹果甲, 有哪些项目]` 变成 `[苹果甲]`，项目问题和回答消失。

建议：后续已有成功对话时隐藏旧重试，或保留完整对话并重新追加该问题。不要用历史重试隐式删除后续内容。

### 3. P2：重定向目标配错，URL 校验仍通过

位置：`scripts/verify-urls.py:196` 至目标核验逻辑。

现在已冻结全部 61 个文章地址，也检查了重定向 source 是否存在；但实际 destination 没有和 fixture 比较。脚本只是检查 fixture 中理想目标是否存在。

本轮在内存中把 configured_redirects 的结果替换为 `{'/life/2024/04/02/024-okr/': '/'}`，保持文件不变，运行 main 仍打印 Failed: 0，返回 0。当前实际配置的目标是正确的，缺陷在于门禁不能发现未来误跳首页。

建议：规范化后比较实际 source 和 destination；Astro 与 Vercel 同一路径的配置也应一致，不能让后读取的配置覆盖并掩盖冲突。

### 4. P2：合法 YAML 带注释时仍会被错误解析

位置：`scripts/verify-urls.py:31`、`:39`。

上轮的简单 `[life, craft]` 已处理。但 `categories: [life, craft] # category notes` 是合法 YAML，当前仍当成整个字符串，生成 `life/craft/category/notes/2026/09/06/test/`。Astro 对同一数组的预期路径是 `life/2026/09/06/test/`，会造成合法文章被校验拒绝。

建议：使用标准 YAML 解析，或直接消费 Astro 内容集合及统一 permalink 函数。再增加一条正则只能继续覆盖个别例子。此处是合法写法的具体复现，不代表当前 61 篇文章校验失败。
